Slopulant watcher architecture

How a pull request on slopulant-monorepo turns into a short list of systems its author should know about: duplicates of what they're building, and systems they read from or feed into. Everything below runs on one local LLM (Qwen3-Coder-Next) plus a small embedding model.

Where things live

data/watcher.db (SQLite)

PR queue, folders, topics, scores, PR metadata. Derived state: safe to delete.

data/llm_cache.json

Identical LLM requests answered locally. File-locked so the demo and evals can share it.

eval/company_manifest.json

Ground truth for the mock company: every system's tables, planted duplicates, PR labels. Never seen by the watcher.

eval/run_eval.py · eval/prompt_lab.py

End-to-end recall@K on the test PRs; signal and prompt comparisons on ~200 queries.
